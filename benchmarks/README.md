# Harness performance benchmarks

Deterministic measurements for the paths users feel first: starting the CLI, reading Session JSONL, draining shell output, and starting the external-control MCP server. No model provider credential is required; the CLI scenario uses a loopback Messages endpoint with a fixed reply.

## Run

```sh
pnpm run bench:perf
pnpm run bench:perf -- --repeats 9 --warmup 1
pnpm run bench:perf -- --scenario session-jsonl --repeats 20
```

The default is 5 recorded samples and at least 1 warmup; `--repeats` must be at least 1. Unknown scenario names fail the run instead of being ignored. Build the workspace first; `bench:perf` does this. Each run writes `raw.jsonl`, `summary.json`, and `summary.md` under `testplace/benchmarks/<timestamp>-<sha>/`, which is not tracked.

An explicit `--output` fails if the directory already exists; `--force` renames the old directory to `<output>.previous-<timestamp>` and keeps it. A scenario that reports `blocked` (for example, an unavailable execution backend) makes the run exit non-zero unless `--allow-blocked` is passed for a deliberate partial diagnostic run.

## Scenarios

| Scenario | Product path | Primary observations |
| --- | --- | --- |
| `cli-startup` | `ligule run --json` against a loopback Messages endpoint | complete one-round duration, spawn-to-first-model-request, result bytes, Node spawn and CLI `--version` baselines |
| `session-jsonl` | `parseSessionBytes`, `readSessionRecord`, `listSessions` over 100 / 2,000 / 10,000 text-event and 1,000 mixed-event corpora | open/parse/list time per workload, per-event cost, byte size, unchanged SHA-256 and mtime, no Session lock |
| `shell-output` | `execTool` with the measured 1 MiB and 5 MiB outputs | duration, benchmark-process RSS delta, bounded/truncated text, per-MiB cost and 5× scaling ratio |
| `mcp-lifecycle` | two real `ligule mcp-server` stdio processes through `@modelcontextprotocol/sdk` | Session creation, one completed Run, restart, persisted receipt read without `session_open`, close and exit |

## Measurement boundaries

- The CLI scenario times the child process from spawn to exit (`fullRunMs`): one complete single-round task including Host/Session startup, the loopback model call, persistence, and exit. `spawnToFirstModelRequestMs` covers spawn through the model request arriving. `nodeProcessMs` and `cliVersionMs` are independent baselines, not a module-load subtraction.
- Session corpus preparation is outside the timed section. The mixed corpus includes user, reasoning, assistant, tool, usage, and compaction events and is validated by the production parser. Reads are repeated on the same bytes, and each read verifies the record hash and mtime and checks that no `.lock` file was created. This is a parse/read/list workload, not a full resume measurement.
- Shell output returns only the product's bounded head/tail text; generated bytes are not returned. The benchmark asserts the truncation marker and bound. `benchmarkProcessRssDeltaBytes` is the benchmark process's resident-set change, not the executed child's peak.
- MCP samples create a Session and one completed Run through a real MCP process, close it, then read the persisted receipt through a new process without `session_open`. The Session hash and mtime must not change and no lock may appear. An unknown-Session `session_not_found` lookup is also exercised before the receipt exists.
- Statistics are grouped by workload. Input-size fields are recorded as context and are not mixed into latency percentiles.

## Environment overrides

- `LIGULE_BENCH_CLI`: absolute path to an installed `ligule` CLI entry (`.../node_modules/ligule/dist/cli.js`). The default is the repository build.
- `LIGULE_BENCH_MCP_SDK`: absolute path to an installed `@modelcontextprotocol/sdk`. The default is the repository dependency.

A scenario reports `blocked` when the host cannot provide the execution backend (for example, the process sandbox is unavailable). It does not synthesize samples. Windows and Linux results are reported separately; absolute timings from different machines are not directly comparable.
