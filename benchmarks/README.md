# Harness performance benchmarks

Deterministic measurements for the paths users feel first: starting the CLI, reading Session JSONL, draining shell output, and starting the external-control MCP server. No model provider credential is required; the CLI scenario uses a loopback Messages endpoint with a fixed reply.

## Run

```sh
pnpm run bench:perf
pnpm run bench:perf -- --repeats 9 --warmup 1
pnpm run bench:perf -- --scenario session-jsonl --repeats 20
```

The default is 5 recorded samples and 1 warmup per scenario. Build the workspace first; `bench:perf` does this. Each run writes `raw.jsonl`, `summary.json`, and `summary.md` under `testplace/benchmarks/<timestamp>-<sha>/`, which is not tracked.

## Scenarios

| Scenario | Product path | Primary observations |
| --- | --- | --- |
| `cli-startup` | `ligule run --json` against a loopback Messages endpoint | full spawn-to-exit duration, result bytes, Node spawn and CLI module-load baselines |
| `session-jsonl` | `parseSessionBytes`, `readSessionRecord`, `listSessions` over fixed 100 / 2,000 / 10,000-event corpora | open/parse/list time, per-event cost, byte size, unchanged SHA-256 and mtime, no Session lock |
| `shell-output` | `execTool` with the measured 1 MiB and 5 MiB outputs | duration, RSS delta, returned text bound, per-MiB cost and 5× scaling ratio |
| `mcp-lifecycle` | real `ligule mcp-server` stdio process through `@modelcontextprotocol/sdk` | initialize, `tools/list`, read-only receipt lookup for an unknown Session, close, process exit |

## Measurement boundaries

- The CLI scenario times the child process from spawn to exit. Model latency is a fixed loopback reply and is included, because first-response time is what a user observes. Node spawn and CLI module load are reported separately.
- Session corpus preparation is outside the timed section. Reads are repeated on the same bytes, and each read verifies the record hash and mtime and checks that no `.lock` file was created.
- Shell output returns only the product's bounded head/tail text; generated bytes and truncation are not counted as returned content. RSS is the benchmark process's resident set change and is approximate.
- MCP initialization is a cold child-process start per sample. The receipt lookup deliberately uses an unknown Session, which exercises the Host lookup and `session_not_found` path without opening a writer; it is not a stored-receipt read.

## Environment overrides

- `LIGULE_BENCH_CLI`: absolute path to an installed `ligule` CLI entry (`.../node_modules/ligule/dist/cli.js`). The default is the repository build.
- `LIGULE_BENCH_MCP_SDK`: absolute path to an installed `@modelcontextprotocol/sdk`. The default is the repository dependency.

A scenario reports `blocked` when the host cannot provide the execution backend (for example, the process sandbox is unavailable). It does not synthesize samples. Windows and Linux results are reported separately; absolute timings from different machines are not directly comparable.
