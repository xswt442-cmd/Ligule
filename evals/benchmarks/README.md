# Agent capability benchmark

Runs a frozen `terminal-bench@2.0` subset through the existing Harbor adapter and keeps Harbor's independent verifier authoritative. The task plan is [plan.json](plan.json); the runner checks prerequisites, writes the exact Harbor job, and preserves raw logs. It never fabricates a score.

## Prerequisites

- Docker daemon reachable (`docker version`).
- `uv` on `PATH`; the runner resolves Harbor `0.25.0` into the uv cache.
- A built CLI tarball: `pnpm --filter ligule run pack-release`, then `--tarball <absolute path>` or `LIGULE_BENCH_TARBALL`.
- Provider settings: `LIGULE_API_KEY`, `LIGULE_BENCH_BASE_URL`, `LIGULE_BENCH_MODEL`; optionally `LIGULE_BENCH_API` (`messages` by default). The base URL must not contain userinfo or credential-like query parameters; records keep only a sanitized URL. `git_sha` identifies the benchmark checkout, while the tarball is identified by its SHA-256; the tarball's source SHA is marked unknown when it cannot be verified.
- Images without Node 24: set `LIGULE_BENCH_NODE_RUNTIME` to an official Linux Node 24 `.tar.gz` and `LIGULE_BENCH_NODE_RUNTIME_SHA256` to its official digest. Images that need a compiler for native npm modules: set `LIGULE_BENCH_BUILD_TOOLS=1`; the adapter installs only `build-essential`/`python3` when missing. `LIGULE_BENCH_APT_MIRROR=tsinghua` uses the adapter's temporary, signature-verified mirror when the default Debian mirror is unreachable.
- The frozen dataset locally. Download once outside tracked files:

```sh
uv run --no-project --with harbor==0.25.0 harbor datasets download terminal-bench@2.0 \
  -o testplace/benchmarks/datasets/terminal-bench@2.0
```

## Run

```sh
pnpm run bench:agent -- --tarball testplace/pack/ligule-0.1.2.tgz
pnpm run bench:agent -- --dataset-dir testplace/benchmarks/datasets/terminal-bench@2.0 --output testplace/benchmarks/agent-run
pnpm run bench:agent -- --tasks fix-git,db-wal-recovery --timeout-ms 7200000
pnpm run bench:agent -- --collect-only --output <existing-run-directory>
```

`--collect-only` recovers an interrupted or externally stopped run: it reads the saved `run.json` experiment identity/model/timestamps, the existing `job.json`, and trial results; it regenerates `manifest.json` and the report and writes `collection.json` without starting Harbor or overwriting the original `run.json`/logs. It refuses to collect when the original `run.json`, identity, or job name is missing, when `--tasks` disagrees with the saved task set, or when `run-state.json` says the original run is still active and its recorded PID is alive. A stale `running` state whose PID is gone is recoverable.

The run directory contains `run.json` (execution status, task counts, checks, tarball SHA-256, model identifiers without secrets, cleanup result), `run-state.json` (written before Harbor starts and updated on return), `job.json` (the exact Harbor job), `harbor/` (Harbor job output), `manifest.json` (generated from actual trial results), report JSON/Markdown (generated by `evals/report`), and stdout/stderr logs.

An explicit `--output` never overwrites an existing directory: the runner fails unless `--force` is passed, in which case the old directory is first verified as a benchmark run (`run.json` with identity) and renamed to `<output>.previous-<timestamp>`. A non-benchmark directory is refused, as is an active run. `--timeout-ms` overrides the computed outer limit; the default scales with task count, concurrency, and the configured setup/agent budgets. The report phase has a separate 10-minute limit (`LIGULE_BENCH_REPORT_TIMEOUT_MS`). On interruption (Ctrl+C/SIGTERM), the runner terminates Harbor's process group (SIGKILL on POSIX, `taskkill /T /F` on Windows), waits for it to stop, records `interrupted` and any termination error, and only then collects the partial result.

Exit codes describe the benchmark execution, not task success: `0` Harbor and report generation completed (inspect `taskCounts` for pass/fail/infra/not-run), `1` Harbor failed, timed out, or report/manifest generation failed, `2` blocked because a prerequisite is missing. A blocked result lists every missing prerequisite; it is not a model score. A timed-out execution records the timeout and incomplete run state. Cleanup targets only this job's exact trial containers (matched by trial name/compose project), never other concurrent runs; any removal failure is recorded.

## Plan and scoring

The plan fixes the dataset version, task IDs, one attempt per task, concurrency, model-call/timeout budget, and the verifier authority. Harbor's task verifier runs in its own environment and decides pass/fail. The runner uses the existing `evals.harbor.ligule_agent:LiguleAgent` adapter and `--allow-full-access` behavior inside the task container; it does not create approvals or read verifier files.

After Harbor returns (including a failed or timed-out execution), the runner scans the actual trial `result.json` files and writes `manifest.json` in the run directory. It maps every planned task to an executed attempt or a `not_run` entry with a reason, records each trial's result and trajectory path, and then invokes the existing report tool. A malformed trial result fails manifest generation instead of being silently reclassified as not-run. The manifest never assigns pass/fail itself:

```sh
uv run --no-project --with harbor==0.25.0 python evals/report/report.py <run-directory> --output-dir <run-directory>-report
```

The runner reports the task-level `pass` / `fail` / `infra_error` / `not_run` counts from `report.json`, not the Harbor process exit code. `taskCounts.startedWithoutResult` separately counts trials that started but produced no result file; the report still places those in `not_run`, so the extra field is the way to distinguish them. If manifest or report generation fails, the run records that error and exits non-zero; raw Harbor output remains untouched. A blocked run has no Harbor results, so it is reported only as blocked. For `attempts_per_task > 1`, missing results are rejected as ambiguous rather than assigned to the wrong attempt.

The report tool validates every attempt against Harbor's result model and keeps pass/fail/not_run/infra_error separate. It does not read Harbor output directly.

`eval:smoke` validates the adapter, ATIF export, and report fixtures without Docker or an external provider; it is infrastructure validation, not a benchmark score. Absolute agent results are meaningful only with the recorded SHA, tarball digest, dataset version, model, budget, and platform.
